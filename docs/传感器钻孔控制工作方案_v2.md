**v2 相对 v1 的变化（按 2026-10-16 确认，控制范围、先跑通主线）：**

1. **换头暂不自动化**：转盘不做自动换头、不做工具映射标定，保持手动换头（降低周日风险）
2. **优先级聚焦**：先打通「传感器阶跃 → 停钻 → 向上抬升固定距离」链路
3. **高度差允许手动测量**；核心产出是「合适的固定抬升高度 A」，电极下移步数按手动测量值执行
4. **实现复用固件已有指令**（`ZDOWN` / `STOP`），不改固件
5. **参数已确认**：传感器 19200、钻孔初值见 3.3；转盘 COM 以实际测试电脑为准（整理版 `code/pc/settings.py` 当前写 COM10，旧文档为 COM11）

## 一、任务与目标（公告拆解）

公告原文（摘要）：

> ② 传感器信号接入控制程序，达到阶跃时停止钻孔并向上移动，向上移动的距离可以固定一个比较好的距离；同时注意安全，即往下钻的距离要设置一个安全值；测量钻孔工具头和电极头的高度差（因为考虑到钻完向上移动了一段距离之后就要换头，要知道电极应该往下走多少步）。DDL 周日，王一凡。

| 编号 | 子目标 | 交付物 |
|---|---|---|
| G1 | 力/称重传感器（RS485 Modbus，19200）信号接入运动控制程序 | `code/pc/force_sensor.py` + 数据落盘 |
| G2 | 钻孔中实时检测「阶跃」（刺穿跌落）→ 停钻、停 Z、向上抬升固定距离 A | `code/pc/step_detect.py` + `code/pc/drill_cycle.py` |
| G3 | 下钻距离设置安全上限 `D_safe`，任何异常都不得超过 | 联锁中止路径 + 报警 |
| G4 | 确定「合适的固定抬升高度 A」；高度差手动测量并记录（供电极下移参考） | 记录表 + 配置值 |

**范围声明**：自动换头（保持手动，程序外）、视觉定位（沿用现有流程）、工具映射标定（二期再做）。

## 三、总体方案

### 3.1 系统架构

```
              ┌───────────────────────────────────────────────┐
              │          code/pc/motion_client.py（主进程）    │
              │  钻孔流程 drill_workflows.py（新命令 DC）      │
              │   ├─ 串口：serial_motion（SPEED/ZDOWN/POS/STOP/DRILL）│
              │   └─ 传感器线程 force_sensor.py（RS485, 19200, │
              │        0x9C40, 32位有符号 + CSV 落盘）         │
              └──────────┬────────────────────────────────────┘
                         │ 115200
                   Arduino Mega2560
                         │
              SPEED 进给 → DRILL ON → ZDOWN（持续下钻）
                         │
     力信号 → 阶跃检测 → STOP（停钻+停Z）→ 记录 Z_stop → SPEED 恢复 → Z -A 抬升
```

### 3.2 钻孔流程状态机（v2 简化版）

状态：`IDLE → PRECHECK → DRILLING → STOP_AND_LIFT → DONE / ABORT`；换头为程序外手动操作。

| 状态 | 动作 | 转移条件 |
|---|---|---|
| IDLE | 等待命令 `DC`；要求 XY 已在孔位、Z 已在待钻高度 | 命令下达 |
| PRECHECK | 读 `POS` 记 `Z_start`；等待传感器首个有效读数；清除旧故障标志 | 通过/失败 |
| DRILLING | `SPEED 进给` → `DRILL ON` → `ZDOWN`；监控：传感器+100ms `POS` 轮询+`LIMIT_STOP` 检查 | 触发 A/B/C |
| 触发-A 阶跃 | 进入 STOP_AND_LIFT，状态 `BREAKTHROUGH` | — |
| 触发-B 限深 | Z 下行累计 ≥ `D_safe` → 状态 `DEPTH_LIMIT` | — |
| 触发-C 异常 | 传感器无数据/连续失败/通信中断（或 `LIMIT_STOP` 兜底触发）→ `SENSOR_FAULT`/`TIMEOUT`/`LIMIT_STOP` | — |
| STOP_AND_LIFT | 统一动作：`STOP`（固件同关钻头）→ `DRILL STATUS` 复核 → `POS` 记 `Z_stop` → `SPEED 恢复` → `Z -A` 抬升 → 到位校验 | 抬升完成 → DONE/ABORT |
| （附）手动 | 人工换头（转盘手动）→ 电极下移参考步数 = A + Δ_head（手动执行，见 WP4） | 程序外 |

**安全红线（硬约束）**

1. 抬升之前必须停钻（`STOP` 后 `DRILL STATUS` 复核为 OFF）。
2. `DRILLING` 状态下（Z 在孔内）禁止任何 XY 移动。
3. 手动换头只允许在 Z 抬升到安全高度后进行。
4. 任何异常路径的最终动作统一为：`STOP → 记录 → 抬升 → 报警`，绝不允许继续下钻。
5. 现场联调全程有人监护，手边可随时断电/按 `E`。

### 3.3 关键参数（v2 已确认值）

| 参数 | 值 | 说明 |
|---|---|---|
| 传感器链路 | 19200 / 从站 1 / `0x9C40`×2 / 高字在前 / 有符号 | COM 口在 `config/force_sensor.json` 覆盖；GUI 与程序不可同时占用 |
| 传感器轮询率 | 按链路可达（实测单帧约 77ms ≈ 10~13 Hz） | 检测窗口相应取 200~300ms |
| 钻孔进给速度 | 20~50 步/秒（0.2~0.5 mm/s），**首测默认 20 步/秒** | `SPEED` 设置，完事恢复 500；跑通后再提速 |
| 阶跃判据 | 峰值跌落 ≥ max(5σ, 绝对下限)，且已出现「加载上升」 | 现场用真实刺穿数据微调（`step_detect.py` 参数） |
| 检测确认窗口 | 200~300 ms | 与轮询率匹配 |
| 安全限深 `D_safe` | 300 步（3 mm）初值 | 仅作传感器未触发时的兜底；首次实测刺穿深度后按“钻深 + 1 mm 余量”定稿；Zmax 限位(D27)为物理兜底 |
| 抬升距离 A | 1000 步（10 mm）初值 | 现场验证手动换头不干涉后定稿 |
| 总超时 `T_max` | 60 s | 未检测到阶跃则中止 |
| 预估过冲 | ≈ 进给速度 × (采样等待+停机) ≈ 0.02~0.05 mm（40 步/s 时；20 步/s 更小） | 在安全裕度内 |

## 四、分步实施计划

### WP1 传感器信号接入（预计 2~3 h）

- 新增 `code/pc/force_sensor.py`：
  - 复用 `tools/rs485/source/modbus_link.py`（懒加载，兼容原工作区路径）；
  - 后台线程连续轮询 `0x9C40`×2 → 32 位有符号（高字在前）组装 → 环形缓冲 + `latest()`；
  - CSV 落盘 `runtime/motion_logs/sensor_<时间>.csv`（ISO 时间 + monotonic + 原始值 + 换算值）；
  - 连续失败计数 + 数据过期时间（供状态机判 `SENSOR_FAULT`）；
  - 支持 `serial` / `tcp` 两种链路（tcp 供无硬件本地测试）。
- 配置：默认值在代码内（19200/从站1/0x9C40），现场用 `config/force_sensor.json` 覆盖（改 COM 口不用动代码）。
- 验证：`mock_slave.py` TCP 端到端（见第五节）；实机与 GUI 读数对比。

### WP2 阶跃检测（预计 3~4 h，离线优先）

- 新增 `code/pc/step_detect.py`（纯逻辑，可单测）：
  - 进入钻孔后先采 1 s 静息基线（μ、σ）；
  - 加载判定：滚动峰值需高出 μ 达到 `load_k·σ`，才认为"已加载"；
  - 触发：当前值比滚动峰值回落 > `max(sigma_k·σ, 绝对下限)`，且峰值在回溯窗口内（防陈旧峰值误触发）。
- 用 mock 穿刺曲线（7.5N→0.15s 跌落）验证触发与延迟；再用真实数据 CSV 离线回放调参。
- 参数全部可配置，不写死。

### WP3 停钻-抬升-限深联锁（预计 3~4 h）

- 新增 `code/pc/drill_cycle.py` 状态机（IO 与传感器依赖注入，便于假硬件测试）：
  - 命令序列：`SPEED 进给` → `DRILL ON` → `ZDOWN` →（监控）→ `STOP` → `DRILL STATUS` 复核 → `POS` 记 `Z_stop` → `SPEED 恢复` → `Z -A` → 到位校验；
  - 监控项：传感器读值（喂给检测器）、100ms `POS`（算深度）、`LIMIT_STOP/运动故障`、超时、传感器过期/连续失败；
  - 所有中止路径走同一「STOP → 记录 → 抬升 → 报警」（`DEPTH_LIMIT / TIMEOUT / SENSOR_FAULT / LIMIT_STOP`）；
  - 事件前后 ±2 s 力曲线另存 `runtime/motion_logs/drill_event_*.csv`，便于复盘。
- 接入入口：`code/pc/drill_workflows.py`（串口适配 + 传感器编排），`code/pc/motion_client.py` 增加 `DC` / `DRILLCYCLE` 命令。
- 单测五场景：正常触发、限深、超时、传感器断线、LIMIT_STOP；断言 `STOP` 先于抬升、`SPEED` 恢复、抬升到位。

### WP4 固定抬升高度与高度差（手动，预计 1~1.5 h，现场）

1. **固定抬升高度 A**：初值 1000 步（10 mm）；用代用材料跑通一遍后，手动换头验证不干涉（不碰蟑螂/夹具）即定稿，写入 `drill_cycle.DrillParams.lift_steps`。
2. **高度差 Δ_head（手动测量，二选一）**：
   - **卡尺法（推荐）**：转盘手动让钻孔头朝下 → 卡尺量「钻头尖端 → 转盘基准面」距离 `h1`；手动转到电极头 → 同法量 `h2`；`Δ_head(步) = (h2 − h1)(mm) × 100`。
   - **触面法**：在固定参考面上分别让两工具尖端轻触（慢速小步逼近），记录两次 `POS Z`，差值为 `Δ_head(步)`。
3. **使用（手动执行）**：钻穿停止记录 `Z_stop` → 程序自动抬升 A → 手动换头 → 电极从抬升位下移参考步数 = **A + Δ_head**（从抬升位算到钻穿终点深度）；操作前用记录表核对。
   注：若电极目标深度与钻穿终点不同（例如需要略浅），在公式上另加偏差，现场确认。

### WP5 本地测试 → 干跑 → 实机（预计 2~3 h）

- 本地（无硬件）：见第五节清单。
- 干跑：不装蟑螂，用泡沫/代用材料跑 3 次（含限深触发 1 次）。
- 实机：有人监护 + 低速 + 限深开启，1 次完整钻孔。

## 六、安全设计

- 限深是硬上限：无论检测是否工作，Z 下行到 `D_safe` 必停；Zmax 限位（D27）为物理兜底。
- 过冲深度 = 进给速度 ×（检测+停机耗时），低速是安全冗余。
- 停钻先于抬升；`STOP` 后必须 `DRILL STATUS` 复核 OFF 才继续。
- 一切异常 → 中止并抬升；`E` 任意时刻全停（含钻头）。
- 联调期间只开 motion_client，关闭 RS485 GUI（串口独占）。
- 手动换头只在 Z 抬升到安全高度后进行。

## 七、验收标准

- [ ] motion_client 运行时传感器连续读数且速率合理（≥10 Hz 实测上限内）
- [ ] 离线回放：已知刺穿点全部触发，静息/无跌落零误报
- [ ] 干跑：阶跃触发后顺序满足 停钻 → 停 Z → 抬升；抬升距离 = A ± 1 步
- [ ] 限深：无阶跃时到达 `D_safe` 必定中止并抬升，日志含 `DEPTH_LIMIT`
- [ ] 传感器异常（拔线/无响应）→ 中止 + 抬升 + 报警
- [ ] `SPEED` 每次钻孔后恢复（测试断言）
- [ ] 固定抬升高度 A 现场验证定稿；高度差 Δ_head 手动测量记录完成（3 组）
- [ ] 力曲线 CSV、日志归档到 `runtime/motion_logs/`
